# 分析设计与证据边界

## 从观察到依赖

每个图顶点是一个已提交事务。操作下标从 0 开始。边保存事务 ID、依赖类型、键、两个操作下标、版本和解释，便于回到原日志核对。

| 边 | 依据 | 强制顺序 |
| --- | --- | --- |
| WR | 读到其他已提交事务的唯一最终版本 | 写者 → 读者 |
| WW | 声明的同键版本顺序中相邻最终写入 | 较早写者 → 较晚写者 |
| RW | 外部/初始读观察的版本早于某个已提交最终写入 | 读者 → 后续写者 |
| RT | 共同观察时钟中 A.end < B.start | A → B |

RW 指向全部已知较晚最终写者。WW 用相邻写者即可表达整个顺序。初始读即使缺少写者之间的顺序，也可确定读者应在全部已提交写者之前。事务内读取自己的最新写入不生成外部读取依赖。

唯一版本和已知同键顺序使依赖图能够表达受支持模型中的串行执行约束。只要没有直接读写异常、缺失信息或预算截断，图无环时由拓扑排序给出可行串行顺序。有环意味着无法满足图上全部必要先后关系。

缺少同键版本顺序时，不枚举所有可能版本顺序，因此无环不等于能够给出完整结论。读取无记录来源的版本可能源于截取日志，报告无法判定，而不直接认定数据库产生了不存在的数据。

## 最短异常环

从每个已提交顶点作广度优先搜索，寻找返回起点的最短路径。返回全图最短的有向简单环，每个事务在闭合前只出现一次。这里“最短”按边数/环内事务数定义；有多个相同长度的环时返回确定的一个。

环查找为 `O(V × (V + E))`，图按资源上限截断后，最短性只针对**实际构建的图**。不声称日志已被全局最小化，也不声称找到了全部异常。为了保证首版可控，使用事务、操作和边预算，而不宣称无界大日志性能。

## 证据复核

复核入口重新解析历史和推导依赖，不调用最短环搜索。它检查：

1. 工具名称、v0.0.1 版本、Schema、模型和异常状态匹配。
2. 证据的每条完整边确实可由当前历史推导，包括操作下标、版本和解释。
3. 边顺序与声明的事务路径一致。
4. 路径闭合，闭合前不重复事务。

完整边中的解释文字也是 v0.0.1 证据结构的一部分；随意更改会导致不匹配。复核器与分析器共享依赖推导规则，其独立性限于“不复用环搜索”。算法正确性另由测试中的完整串行重放 oracle 检查。

复核不检查最短性、所有报告统计、报告的其他 findings、数字签名或日志身份。它验证一个反例，不是审计签名服务。资源截断时，只能验证保留下来的边；合法但依赖未保留的环可能无法复核，不能把复核失败当作无异常证明。

## 模块职责

| 模块 | 责任 |
| --- | --- |
| `types.mbt` | 输入、依赖、结果类型 |
| `json_guard.mbt` / `parse.mbt` | 深度、重复键、结构和语义校验 |
| `analyze.mbt` | 写入来源、版本顺序、依赖和直接异常 |
| `graph.mbt` | 最短环与拓扑顺序 |
| `report.mbt` / `render.mbt` | JSON/文本/Markdown/DOT、证据复核 |
| `bridge/` | MoonBit 对 JavaScript 的导出 |
| `cmd/` | 本地 I/O、参数、退出码与轻量 SDK |
| `scripts/oracle.mjs` | 测试用全事务排列重放与独立 DFS |

分析核心没有数据库、网络或 npm 依赖，使用 MoonBit 自带的 core/json。Node.js CLI 限制输入字节、拒绝覆盖现有文件，并在导出失败时清理本次已创建的配套文件。没有后台服务或遥测。
