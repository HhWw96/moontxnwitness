# 面向通用事务异常分析基础库

项目定位调整为 **MoonTxnWitness——MoonBit 通用事务异常分析基础库**。目标是提供可嵌入的异常检测、形式模型反证、解释、缩减和证据回放；SQL／ORM 采集器是输入适配层。定位表示发展目标，不表示 v0.3.0 已完成 Elle 的全部能力。

以固定 Elle 提交 `4e359e597c52938b0afebb8bc42273914d68a424` 的实现和公开模型定义为共同范围基准，当前树源码为实现依据。Elle 本身也需要满足数据类型、操作和观察约束，并不承诺自动理解任意 SQL。其公开说明强调非谓词异常；关系谓词分类是本项目需单独设计、验证的扩展，不能写成已经达到 Elle 同等覆盖。

| 能力 | 当前已实现的范围 | 下一步需要交付的实质能力 |
| --- | --- | --- |
| G0、G1c、G2-item | 点寄存器逐类别搜索与见证，原最短环接口保留 | 统一三模型图接口；多重边、不同最短环的独立搜索验证 |
| G1a、G1b、INT | 寄存器及声明范围的列表原始来源检查 | 扩展多追加、保存点、中间版本、未确认提交的来源处理 |
| G-single、G-nonadjacent | 已有受支持范围的非相邻反依赖检查；不是全部类别接口 | 独立 G-single；item／predicate、process／realtime 的规则与证据分离 |
| 丢失更新、未来读取、脏更新 | 部分案例由既有反证发现；不等于具有各类别的独立完整实现 | 逐类定义直接检测依据、原始证据和模型蕴含关系 |
| 六个形式模型 | 寄存器和受限列表逐规则检查，必要检查不全保留无法判定 | 正式覆盖表、可执行的规则集合和共同范围差分；不能只增加模型名称 |
| 列表数据模型 | 有界精确解释器及受限图分类 | 同键多追加、回滚／中间读取和可推导顺序；推断不能改写原始事实 |
| 关系数据模型 | 有界精确串行分析；点读、完整集合／空结果和写影响 | G0、G1a、G1b、G1c、G2-item、谓词 G2 及六模型适用性；来源不足不能接受模型 |
| 会话与实时 | 在有明确来源的范围支持严格模型检查 | 会话先后和真实调用完成关系分别建边，不使用 BEGIN 代替逻辑快照 |
| 业务采集 | 指定 engine／工厂的诊断观察；固定配置可投射三模型事实 | 与 ORM 品牌无关的表／列／键／谓词配置和 SQL 结构识别，同一配置跨多个业务使用 |
| Elle 对照 | 仓库有冻结转换器及既有实验；不以实验数量推定完整一致 | 固定原始事实，发布每类别、每模型的一致／差异／unknown／超时／失败明细 |

所有模型结果区分“存在反证”“所需检查均完成且与所给事实相容”“无法判定”“未支持”。相容只针对输入历史及所给事实，不认证数据库全局实现。可靠反证不能被其它规则的超时掩盖；没有发现环也不能在缺少必要来源时变成相容。

关系分类必须把实际返回集合、查询完整性、谓词范围和写影响分开；区分 item 与 predicate 反依赖。零行条件写、UPDATE 等待后重检、删除与跨谓词更新需要独立来源语义，不能用 RETURNING 冒充完整谓词读取。严格级别还要有可验证的实时证据。

通用采集按能力层次说明：启动诊断可以记录未识别 SQL；配置化语义投射只对明确证明的语句生效；完整隔离分析还要求来源闭包和采集窗口。应覆盖普通用户表、连接池、同步／异步、事务和保存点，拒绝将第二个固定 ORM 案例当作通用性完成。
