## 性能准入

| 指标 | 门槛 |
| --- | ---: |
| 完整图组几何平均提速 | ≥1.3× |
| 图组峰值 RSS 比 | ≤0.8 |
| 9–12 事务搜索组提速 | ≥1.5× |
| 512 事务缩减提速 | ≥1.5× |
| 完整采集 C/A 吞吐 | ≥0.90 |
| 完整采集 C/A P95 | ≤1.15 |
| 共同负载 P95 回退 | 不超过 10% 或 2 ms 较大值 |

A 原业务，B 来源开启/事件关闭，C 完整来源/采集/持久化；列和 sidecar 同支持范围比较。四个负载：4096 键/1 连接；4096/4；32/8 且 90% 更新在 4 热键；4096/4 CRUD+负读。每单元 15 秒预热、60 秒发起、最多 30 秒排空，三批 ABC/BCA/CAB。记录所有尝试、提交、失败、日志缺失、CPU/RSS/WAL/阻塞/同步完成时间，耗尽预算不能达标。

分析性能保持 5 次预热 + 30 样本 × 3 批独立进程，同机/工具链/输入/完整输出。失败保留并先修实现，不重复至偶然通过。

## 发布门禁

源码冻结 → 跨目标回归 → 真实数据库 → 适用性能 → 独立技术验证 → GitHub/Mooncakes → 公开下载摘要与全新消费者。

技术验收明确标记“独立 AI 验收”。发布前从独立干净源码目录验收；发布后用公开下载包再做干净消费者验收，不能声称未发布包已公开下载。未执行项不得打勾。CI 上传实际编译 core 文件，保留以前仅记录摘要的限制说明。

开发者不单独签署自己的技术验收；独立验证不得修改预期来消除差异。功能验证、真实使用反馈与生产采用分别记录。
