# 源码、运行时与历史证据的存放约定

当前开发树只保存当前实现、完整测试所需输入、真实案例的必要证据，以及兼容旧复现包的固定运行时。历史完整源码通过 Git 提交和发布标签定位，不再放进验证报告目录复制一份。

v0.3.0 提交 `26cc7d4a7f1fb6f9eeacc491daea5f651a733c5b` 的树包含 56,962 个文件、3,420,924,346 字节；本次清理保留的原路径为 9,861 个、原展开体积 469,145,773 字节，另有少量治理程序、说明及本次新验收收据的更新。移出的 47,101 个文件全部位于 `verification/`，共 2,951,778,573 字节。数字按 Git blob 展开大小计算，不是压缩下载大小或磁盘实占。

移出清单及每个文件的原 Git 对象、字节数保存在 [压缩清单](archive/v0.3.0-tree-removals.json.gz)。原文件未从 v0.3.0 标签或已有工作区删除；查看单个文件可执行 `git show v0.3.0:verification/原路径`，也可在独立目录检出该标签复现实验。

| 内容 | 存放方式 |
| --- | --- |
| 当前 MoonBit 核心、SDK、适配器 | `src/`、`cmd/`、`integrations/` |
| 当前测试的冻结输入和独立解释器 | `fixtures/` 及保留的少量 `verification/` 路径 |
| 旧证据严格回放所需的真实运行时 | `cmd/legacy/`，保留原摘要及许可；属于执行依赖 |
| 历史完整源码与旧实验结果 | 原 Git 提交／发布标签；新增大型实验通过 CI 工件或发布附件交付 |
| 新产生的运行输出、候选源码、解压下载 | 被忽略的 `verification/`、`artifacts/`；不使用 `git add -f` 批量纳入 |
| 新的公开验收材料 | 精选摘要、输入、复现命令、源提交、附件 URL 与 SHA-256，逐项审查后纳入 |

`python scripts/repository_hygiene.py` 检查暂存区，限制文件总量、展开体积、新大文件、源码副本和生成目录。冻结的大输入与外部独立验证源码按原 Git 对象放行；不能借旧路径替换成新内容。CI 在安装依赖、编译之前执行同一检查。需要修改额度时，必须同时解释实际用途和替代归档位置。

本次是向前提交的文件树整理，**没有重写 Git 历史**。因此检出和 GitHub 自动源码归档会变小，普通全历史克隆仍可能下载旧对象。完整缩小克隆需要另行迁移历史证据并制定引用、标签和使用者迁移方案；不会在本次整理中强推或移动既有发布标签。日常开发可使用 `git clone --depth 1`；需要历史审计时再获取原标签。

历史文档的相对链接若已移出当前树，应在 v0.3.0 标签下访问。当前运行测试所需的文件必须在当前树，不允许用“去旧标签查找”掩盖测试缺失。
