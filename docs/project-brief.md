# MoonTxnWitness 项目说明

**MoonTxnWitness——MoonBit 通用事务异常分析基础库。** 面向数据库测试、后端回归与故障排查，将业务观察转化为可核验的事务事实，提供异常检测、形式模型反证、解释、反例缩减和证据重放。MoonBit 实现分析核心，通过 Mooncakes 库、JavaScript SDK 和 CLI 供其他工具嵌入；Python 适配层负责 PostgreSQL 业务观察与来源采集。

当前公开版本 v0.3.0 已有寄存器、追加列表、关系行集合三种分析模型；寄存器和声明范围的列表支持逐异常与六个形式模型检查。通用启动诊断可作用于指定 SQLAlchemy engine 或局部 psycopg 工厂；配置化来源入口把受支持的真实 SQL、参数、实际返回和事务结果交给核心核验，无需手写事务历史。模型、适配层和完整来源分析是分别声明的能力，详见[支持矩阵](stable-scope.md)。

实际工作流包括：采集业务运行，分析来源和异常，保留操作级依赖见证，重验并缩减反例，封装原始记录及报告，再用于修复后的回归。读取来源、最终写、撤销、未知提交和实际结果交付始终分开记录；预算耗尽和观察不足保持无法判定。原始事实不被推断顺序覆盖，旧证据通过明确版本和原运行时校验。

已完成的 MLflow 原生 HTTP `log-batch` 案例针对公开加锁顺序故障，修复前后各使用 30 个固定种子。以原生 `40P01` 确认死锁，真实重跑将案例由 1,000 键缩至 623 键，同一最终请求在修复前后各完成三次对照。死锁单列执行故障，不冒充隔离模型违反；未完成全量单删检查，所以保留 `oneMinimal=false`。入口为 `node examples/mlflow-http-roundtrip.mjs`；该命令离线重放既有真实记录，[原始案例](mlflow-http-case.md)另有实际执行说明。

相对已有工具的开发重点是 MoonBit 原生可嵌入核心、业务观察到模型事实的配置化接口，以及统一的来源、反例缩减和修复回归链路。以 [Elle](https://github.com/jepsen-io/elle) 的异常与模型定义为对照，生产分析器独立实现，不调用 Elle；对照范围与许可见 [THIRD_PARTY.md](../THIRD_PARTY.md)。这些是可复核的产品方向与已有能力，不等于已经全面替代 Elle。

下一步优先补足关系完整分类、列表复杂事务、逐类别及逐模型对照，并使语义采集配置脱离固定 ORM。当前仍不支持的能力按[Elle 对齐表](elle-alignment.md)和[开发顺序](roadmap-v0.4.0.md)逐项落实，不能通过把六个名称列出来、增加一个固定业务案例或改变申报措辞代替实现。

下载与运行见[首页](../README.md)，实际构建、测试、独立核对和安装状态以发布收据为准。性能按同输入、同完整输出测量，不将局部优化等同于完整业务吞吐提升。当前树采用[源码与历史证据分离](repository-layout.md)，历史材料可按发布标签恢复，当前测试必需输入仍随树保留。
