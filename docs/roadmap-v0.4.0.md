# v0.3.0 之后的开发顺序

本轮以[Elle 能力差距表](elle-alignment.md)为范围依据，稳定切片完成后依次发布小版本。版本号是交付顺序，不用发版替代功能完成，仅记录实际完成并验证的功能。

| 阶段 | 开发任务 | 可执行验收与交付 |
| --- | --- | --- |
| 1：仓库治理 | 移出历次验证输出和嵌套源码；保留测试闭包；新增 Git 暂存区检查和 CI | 当前源码重新构建，既有测试与旧胶囊回放；公布精简前后计数、原标签、可恢复清单；不宣称历史下载已压缩 |
| 2：统一异常基础层 | 三模型复用整数事务／对象索引与带来源的 WW、WR、RW 边；独立选择类别；建立异常蕴含规则表 | 各类别有正例、反例、篡改检查；小图穷举含多重边和环首尾规则；保持旧分析语义与算法标识 |
| 3：关系分类 | 先点读写的 G0／G1／G2-item，再完整谓词／空结果的 G2；最后组合六模型与严格证据 | 独立关系解释器、跨谓词更新、删除、零行写、来源缺失；支持规则逐项完成才允许相容；缺失规则可继续给出可靠反证 |
| 4：列表及 Elle 共同范围 | 解除分类对单追加的限制，补齐 G-single、会话／实时类别及直接异常 | 固定 Elle 提交及共同原始输入；按模型、类别发布对照明细和全部差异；先修正来源与定义差异，不改预期凑一致 |
| 5：配置化通用采集 | SQL 结构识别、表配置和来源安装与具体 ORM 分离；支持普通表和两种独立业务使用同一接口 | 业务只安装配置；实际 fetch、提交结果、保存点及重试身份不变；未知 SQL 可诊断、语义不明保留缺口；三模型端到端分析、缩减与重放 |
| 6：性能与排障收敛 | 图索引和分配优化、候选来源索引复用、分段批量持久化；新增业务故障闭环 | 同输入同完整输出和 v0.3.0 比较；中位数、P95、RSS、输出体积和采集 C/A 分开；真实故障修复前后对照，SQLSTATE 故障不冒充隔离违反 |
| 汇总版 | 冻结已经验证的公共契约和推荐入口；完善 API 文档与使用示例 | 全新安装、完整可运行案例、跨目标及适用数据库测试；逐项核对支持矩阵、安装与示例 |

性能工作贯穿各阶段。先移除重复编码与多余 IO，再共享不可变索引，最后优化分类搜索和缩减。正式测量仍采用原成对协议和共同控制组；新增更多分类检查的成本单独报告，不能与旧版少检查的调用直接计算提速。精确枚举上限与图分析容量分开。

实施入口与依赖：

1. 先从 `src/classification_v3.mbt` 和 `src/classification_models_v3.mbt` 提取可复用的带类型边、来源和逐规则预算。旧寄存器已有类型化接口；为列表、关系及分类增加相应的结构化库入口，JSON 保留为互操作格式，避免每层重编码。
2. 关系图适配以 `src/relation_v3.mbt` 的 `RelationV3Parsed`、来源前驱、保存点操作和完整查询语义为输入。优先新增独立关系分类模块和解释器对照；不通过把原来的 `supported` 判断改为 true 来放开模型。类别证据必须能够回指具体查询、行版本、写效果及完整性事实。
3. 模型投射配置从 `integrations/python/moontxnwitness_capture/profiles/model_profile.py`、`profiles/fastapi_users.py` 中提取；`instrumentation.py` 继续只负责实际交付和生命周期。新通用配置应被不同业务复用，原固定 profile 成为预置配置而非另一路核心实现。
4. `cmd/classification-models.mjs` 及 CLI 在核心规则通过后接入；核验器独立重算来源、类别和模型组合，缩减固定保留目标异常及其来源闭包。
5. 将旧回放运行时逐步拆成按摘要固定的兼容附件，减少当前包内的重复运行时。旧证据的预算和执行规则保留；附件缺失明确报错。新证据将语义算法／契约标识与产品发版号分开，不能每发一个版本就再复制整套历史源码。拆分前必须验证离线安装与历史重放方案。
