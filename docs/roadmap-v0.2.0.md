# MoonTxnWitness v0.1.1 至 v0.2.0 实施计划

计划日期：2026 年 10 月 20 日。基线版本：v0.1.0，本地提交 `064f84f2fe0fefe390c0fb60cbaefca5158a440a`。开发已从 v0.1.1 开始；未验收项目仍为计划，当前进度见 [开发状态](development-status.md)。实现、发布及赛事审核分别记录。

本轮把重点从预设历史上的性能改进，扩展为普通业务可接入、不同模型可分析、异常可解释、真实问题可复现和修复可回归。采用八个可分别发布的小版本，最后以 v0.2.0 冻结接口和支持范围；性能优化与正确性验证贯穿每版。

## 交付范围

本轮逐项补齐自动采集、普通表版本溯源、ORM 接入、多种数据模型、异常及隔离模型分类、真实业务排障和成熟工具对照。数据模型覆盖唯一版本寄存器、列表追加和受限关系行集合；分类覆盖六类明确版本化定义的模型反证报告。

自动 SQL 支持先覆盖显式事务中的主键点读写、单表主键范围，以及有类型字段的等值和区间 AND 谓词。JOIN、任意聚合、子查询、任意存储过程和未理解的触发器副作用不在 v0.2.0 稳定范围内。它们必须被识别为覆盖缺口，不能被静默转换成点读写后给出完整结论。这样可以验证承诺的全部范围，而不是承诺任意 SQL 的通用分析。

采集器只负责适配数据库和记录事实。模型语义、来源校验、依赖构建、异常分类、搜索、缩减与证据验证继续主要由 MoonBit 实现。

## v0.1.1 驱动自动采集和测量基线

实现 psycopg 连接工厂、连接及游标包装。自动记录受支持 SQL 的调用、实际获取的行、影响行数、异常、事务请求和提交或回滚确认。覆盖同步及异步主要路径，区分 execute 与后续 fetch，不能把执行成功等同于已经完整读取结果。

业务只配置表、键及已有版本字段，或注册明确的 SQL 语义映射；由采集器生成原始事件及规范化历史，不要求用户手写 `ops`、`initial`、`status` 或 `versionOrders`。SQL 子集采用结构化识别，不依赖正则表达式猜测任意 SQL 的含义。

原始事件附带事件序号、连接与事务标识、时钟域、采集器版本、完整性及覆盖信息。缺少事件、可检测的入口绕过、流式结果未取完、不支持语句或日志写入失败进入覆盖报告。包装器无法自动发现其他应用和未知连接；外部活动无法核实时标明范围未知，完整结论须有受控部署或数据库级交叉核对依据。

自动生成初始状态须关联一致初始快照与采集起点，并识别采集开始前已在途的事务；不能把某键第一次读取的值冒充初始版本。条件不满足时只产出原始日志和覆盖缺口，不生成看似完整的历史。

**验收：**一个采集器开发前已存在、具有可靠版本字段的应用，仅修改连接入口和配置即可导出可分析历史。冻结应用提交和许可证，公布代码差异。覆盖提交、回滚、错误及日志截断，输出至少一份独立重放记录。

**性能：**固定公开 v0.1.0 源码、编译器、运行时、输入和完整输出，新增不可覆盖的基线清单。优化前冻结 9–12 事务困难组及 512 事务噪声组，公开生成器、种子、输入哈希和 v0.1.0 原始测量，不按后续提速效果更换样本。分别测量采集、规范化、解析、索引和依赖、SCC 与最短环、搜索、缩减、完整输出；保留旧 v0.0.6 比较链。

## v0.1.2 普通业务表的可靠版本来源

完成两个最小原型后选择稳定方案：附加版本列加事务内触发器，或独立元数据表加事务内触发器。比较迁移成本、业务列布局变化、权限、WAL、锁等待、死锁、吞吐和延迟。需要数据库安装步骤和额外元数据不是零改造，必须计入接入成本。

每次写产生唯一版本身份，即使业务值相同；身份不表示提交顺序。支持同事务多次写、插入、删除、删除墓碑和删除后重插。附加版本列本身不能在行删除后提供墓碑，仍须配套事务内删除元数据或经验证的负读来源机制，并将零行返回与其同语句快照关联；不能把“不存在”直接当作某次删除的唯一身份。版本来源来自可重放的数据库事实，不能用业务值、`xmin`、`ctid`、sequence、墙钟或线程返回顺序替代完整版本事实。

业务结果与版本元数据必须处于同一语句快照；不能先读取业务行，再发另一条语句查询元数据。首次回填使用可证明一致的初始化窗口；外部写者、元数据缺失、未理解的触发器副作用必须保留为覆盖缺口。旁路审计或逻辑解码可作为补充，不能替代读结果和失败尝试采集。

**验收：**在原本没有版本列的普通表上，独立重放核对重复值、多写者、多次更新、删除重插和回滚。原始业务与完整接入后的确定性业务测试中，返回列、返回值、影响行数、异常和事务边界一致。自由并发结果不要求逐次完全相同，但必须比较额外锁、死锁及异常率的变化。

**设计关卡：**若两种原型都不能可靠关联读取来源，不能进入“普通表已支持”状态；保留原型和失败证据，继续解决该关卡。不能以用户自行添加唯一业务值规避此项。

## v0.1.3 ORM 和事务生命周期

提供 SQLAlchemy 接入层，覆盖常用同步及异步连接、连接池复用和声明的原生 SQL 路径。声明 raw SQL、bulk 操作及绕过 hook 的支持边界，避免 ORM 成功接入后遗漏实际 SQL。

保存点按操作作用域建模：回滚撤销写效果，但已经返回给业务的读取结果仍属于原始观察。验证自身写后读、回滚后再读、嵌套保存点、自动提交、事务级错误及新事务重试，不把重试混入原事务。

COMMIT 后断连保留未知结果。有可靠持久证据时可以确认部分事务已提交；暂未查询到提交标记不能证明回滚，也不能为采集标记悄悄把只读事务改成写事务。未解决的未知结果进入无法判定原因。

**验收：**原生 SQL 和 ORM 各接入一个既有项目。首次接入目标为每项目 30 分钟以内、业务代码改动不超过 20 行；表映射、SQL 配置、数据库迁移、权限和安装步骤另行公开计数。实际用时由真实操作记录提供，自动化安装时间不能代替人工接入时间。

**故障验收：**丢日志、采集进程退出、数据库错误、保存点回滚、池连接复用及 COMMIT 后断连均有自动故障测试；支持范围内的历史无需手工修订即可进入分析和复现。

**性能：**避免每次查询重复解析相同结构，批量持久化事件但不吞掉缺失或写入错误；记录缓存占用、缓冲上限和恢复成本。

## v0.1.4 列表追加模型

新增列表读取与追加语义；每键追加事件使用唯一身份，允许不同身份携带相同业务值。读取列表的顺序用于约束版本前缀，不能把客户端创建身份的顺序当作已确认写入顺序。

支持不相容列表顺序、读到已回滚追加、外部读到事务中间追加、内部读写不一致和重复读取元素等证据。重复提交同一追加身份属于无效输入；读取结果出现重复身份则可能是异常，两者不能混淆。

**验收：**新增 MoonBit 分析、证据验证和缩减，并用独立列表状态机穷举小历史。保留点读写接口；混合模型事务仅在组合语义和独立重放通过后启用，否则明确拒绝。新模型先建立自己的性能基线，不与旧寄存器摘要比较。

**性能：**共享身份索引与列表前缀表示，减少重复扫描及完整列表复制；所有推断保留来源，缩减后重新验证追加来源和顺序约束。

## v0.1.5 关系行集合和受限谓词

第三种模型以有主键、有类型字段的行集合为状态，支持点查、主键范围、字段等值和区间 AND 谓词，以及 Insert、Update、Delete。首先支持明确的整数、文本和布尔比较规则；NULL 和排序规则只有在三值逻辑及比较语义实现并验证后才纳入支持。

采集完整结果集及空结果，保留行版本、写入前后值、墓碑和事务生命周期。验证插入、删除重插、更新跨入或跨出谓词、重复值、空区间和受支持的多行更新。没有返回某行并不天然构成幻读证据，必须证明查询语义、初始状态和相关写入的覆盖完整。

首版先用独立关系解释器穷举小历史、构造可解释证据，再增加经过核对的范围与字段索引。不能为每个范围凭空制造一个虚拟键后直接套用点读写推理。COUNT、LIMIT、JOIN、子查询和任意表达式仍报告未覆盖；返回行后在业务代码中计数不等于已经支持 SQL 聚合。

**验收：**至少 1,000 份预先冻结种子的小规模关系历史，由独立解释器核对查询结果、写效果和串行可行性；每个边界另有确定性反例。范围来源、旁路写者或初始化事实不全时必须无法判定，不得输出完整无异常结论。

**性能：**先正确实现，再用区间索引和写集合索引避免对全部查询与写入逐对扫描；密集相交导致的真实依赖仍完整保留。

## v0.1.6 异常分类及 Elle 对照

建立独立、版本化的异常定义表、模型定义表和反证映射。稳定目标为下表六类明确的定义，其中快照隔离采用 Elle 的 generalized SI，不能混称原始 Adya PL-SI。数据库配置的隔离级别单独保存，不能与形式化模型混为同一字段。

| 计划固定的定义标识 | 必须完成的反证规则 |
| --- | --- |
| `adya-pl-1-v1` | G0 写依赖环 |
| `adya-pl-2-v1` | G1a、G1b、G1c |
| `adya-pl-2.99-v1` | G1a、G1b、G1c、G2-item；G2-item 要求环中至少一条项目反依赖，允许同环另有谓词反依赖 |
| `elle-generalized-si-v1` | 内部一致性违反、G1a、G1b、G1c、G-nonadjacent；后者含至少一条反依赖，且反依赖在环上两两不相邻，首尾也计相邻 |
| `adya-pl-3-v1` | G1a、G1b、G1c、G2；项目及谓词反依赖都计入 |
| `strict-pl-ss-v1` | G1a、G1b，以及加入已证明实时关系后的图上对应 G1c、G2 规则 |

此表是要实现和独立验证的定义契约，不是当前功能清单。先固定参考文献、Elle 提交和规则测试，再冻结标识。G-single 是 G-nonadjacent 的特例，不能替代后者；一般含相邻反依赖的 G2 环可能被 generalized SI 允许。[Generalized SI 定义](https://jepsen.io/consistency/models/snapshot-isolation)、[G-nonadjacent 定义](https://jepsen.io/consistency/phenomena/g-nonadjacent)

实时边必须来自可比较时钟域中的调用和完成事件，或可核验的因果关系；不同机器墙钟的数字大小不足以建立实时事实。

原始 Adya PL-SI 还涉及系统选择的逻辑快照起点，不能用客户端 BEGIN 或首语句时间替代。该扩展不混入上述稳定 SI 名称；若后续加入，须独立定义和采集逻辑起点证据，信息不足保持无法判定。[Adya 原始论文](https://publications.csail.mit.edu/lcs/pubs/pdf/MIT-LCS-TR-786.pdf)

第一层输出可验证异常：G0、G1a、G1b、G1c、G-nonadjacent，以及 G-single、G2 的项目环和谓词环分类，严格模型另有含实时关系的证据；补充内部不一致及列表专属异常。谓词反依赖是边，只有满足对应环及规则才形成该类异常。SI 相关反证按上表固定定义实现，不能用“未发现单条反依赖环”断言 SI 成立。

第二层输出业务名称：丢失更新、写偏斜、不可重复读、幻读等。只有满足具体操作模式和来源证据时才附加名称；不将任意反依赖环都称为写偏斜，不将自己修改后的读取变化称为不可重复读。

第三层输出被证据排除的模型，并分别给出已发现异常、排除模型、未发现违反、覆盖情况和无法判定原因。仅当某个已记录历史在声明模型和事实下被完整验证时，才能给出该历史范围内的确定结论；报告不认证数据库所有执行的隔离级别。

**验收：**每个异常和模型映射均有最小正例、边界负例和独立证据验证器。全局最短环与某异常类别的最短证据分别处理，不能因为一个全局最短环不符合类别就宣称该类异常不存在。六类定义的计划规则必须逐条完成，未完成项阻止其被标记为稳定支持。

**独立模型核验：**串行重放只用于声明的串行顺序可行性。RC、RR 和 SI 等分类另用独立多版本可见性与提交冲突解释器，按固定模型约束枚举；generalized SI 解释器固定 INT、EXT、PREFIX、NoConflict 约束，不额外附加客户端实时顺序。SI 可允许非串行的写偏斜，不能因串行搜索无解而判它违反。精确搜索、视图或冲突可串行化的关系须在模型契约中证明；仅有串行搜索无解而无相应类别证据时，报告 `serial-order-unsat`，不能自动改名为 G2 或某隔离异常。

**Elle 对照：**固定 Elle 提交、依赖、模型设置和转换器版本；同一份原始事实独立转换，不传入本工具搜索推断的版本顺序。寄存器和列表的共同表达范围要求零未解释判断分歧；受限关系模型由独立关系解释器核验，不声称 Elle 对照覆盖其未支持的谓词范围。Elle 是参考工具，小历史同时按对应模型的独立解释器核验。

**性能：**复用各模型公共索引、依赖图和事实校验；分类环按规则搜索，避免重复生成完整报告。不能用复用通用最短环来替代必要的分类检查。

## v0.1.7 真实业务排障及修复回归

至少使用两个在采集器之前已经存在的开源业务项目，涵盖原生 SQL 和 ORM 接入；至少一个问题来自已有缺陷、公开故障或可独立核验的实际业务问题。记录项目提交、许可证、受影响版本、问题来源和修复提交。历史数据库缺陷要注明受影响版本，不描述成当前 PostgreSQL 18 的新发现。

固定业务代码和负载后，运行至少 30 个预先登记种子的自由并发测试，保留部分种子作最终留出验证。确定性屏障示例继续用于回归，但不作为自由业务排障的替代。业务不变量由独立检查器验证，既保存异常运行，也保存未发现异常和无法分析的运行。

每个案例完成“原始数据库响应→分析→缩减→复现→业务修复→同负载回归”。修复可采用原子条件更新、正确锁、数据库约束或可序列化事务与正确重试，按业务选择；不只修改报告标签。业务不变量通过不等于可串行化证明。

**验收：**全程不手改历史；至少一名实际使用者或独立开发者按 README 在全新环境完成安装和复现，并保留真实操作记录。若尚未取得人工记录，该项保持待完成，不由 CI 或自动化脚本代填。

**增量价值：**分别测量接入步骤、业务改动、首次定位和复现成本、运行依赖和运行时间。原始结果支持后才声称降低成本或缩短排障时间；不能把 Elle 已有的见证或缩减能力当作它缺少的创新。

## v0.1.8 性能和规模收敛

对已有点读写能力，用 v0.1.0 的同输入、同语义、完整报告作直接基线；继续保留 v0.0.6 历史链。列表和关系模型各用最初通过独立验证的版本作自身基线。新模型或新增分类工作不能与旧版较少的输出范围混比。推荐 v3 完整分类路径另报绝对时间、P95、RSS、输出大小及自身基线，不能只展示兼容 v2 路径的提速。

| 指标 | 本轮内部目标 | 比较范围 |
| --- | --- | --- |
| 完整接入开销 | 吞吐下降不超过 10%，P95 延迟增加不超过 15% | 相同业务、数据、并发与数据库，完整接入 C 对原始业务 A，包含版本溯源和采集成本 |
| 图分析 | 完整分析中位数的几何平均提速至少 1.3 倍；峰值 RSS 比率不超过 0.8 | v0.1.0 固定旧图组，同报告契约、全部依赖及来源 |
| 精确搜索 | 固定 9–12 事务困难组提速至少 1.5 倍 | 相同事实、模型、预算与结论；另报操作检查数及缓存占用 |
| 反例缩减 | 固定 512 事务噪声组提速至少 1.5 倍 | 相同异常判定规则、预算与事务单最小要求 |
| 非目标负载 | P95 回退不超过 10% 或 2 毫秒中的较大值 | 每版共同支持的固定控制组 |

上述为工程验收目标，不是官方获奖分数线。旧的 6–8 事务搜索有些已经接近 1 毫秒，不再只用微小样本追逐倍数。目标未达时保留原始测量、定位瓶颈和继续优化，不将冒烟测试写成完整验收。

优化集中在原始日志流式处理、整数索引复用、谓词候选索引、模型共享事实、减少中间分配、搜索状态回滚、来源闭包缩减和完整报告输出。缓存键包含模型版本、已执行事务、当前状态及全部有关约束；只有完整证明失败的状态才能记作无解。缓存容量和预算不能改变正确性。

大图入口单独设计，候选上限为 2,048 事务、50,000 操作、250,000 依赖边，经过规模阶梯和资源预算验证后启用；未通过则不提高额度。精确搜索继续保留 12 个已提交事务的已验证上限，不将大图容量等同于精确枚举容量。新增模型的精确入口按独立验证通过的额度声明，不自动继承寄存器上限。

长业务流按读取来源及范围写入事实闭包切窗，公布已分析、无法判定、不支持和未覆盖比例。不得任意切片后补造初始事实；跨窗依赖不完整时保持无法判定。保留最短环原定义、全部来源及单最小缩减约定，不通过删传递边、漏证据或未完成单删检查提高指标。

## 测量和正确性统一门槛

分析性能每场景预热 5 次、正式测量 30 次、3 批独立进程交替运行；保存输入哈希、机器、工具链、原始样本、中位数、P95、冷启动、首次分析、峰值 RSS 和输出字节。

接入测量分三组：A 为原始业务及原表结构，B 为安装版本溯源但关闭事件采集，C 为完整接入。固定持续时间和并发度，至少 3 批交替测量，分别报告 B/A、C/B、C/A。10% 吞吐及 15% P95 门槛用于 C/A 完整成本；不能在开关两组都保留触发器后隐藏版本溯源成本。另报 CPU、WAL、存储、锁等待、死锁、异常率和日志缺失情况。

Elle 与 MoonTxnWitness 分别比较核心判断、证据、缩减、完整报告及端到端流程；冷启动与热运行分列，进程 RSS 与进程 RSS 比较，不用 JVM 堆大小对照另一方整个进程。转换成本和采集成本也独立记录。

保留 v0.1.0 的每目标 94 项核心测试、10,320 份独立历史核对、6,373 份环证据、2,542 份解析差分输入和 75 项 CLI 检查，按新契约增加真实边界测试，不靠重复用例充数。JS、Wasm GC、Wasm 与 Linux Native 对共同输入的语义结果一致，原始计数及性能可不同。

新增测试必须覆盖重复值、删除重插、多操作事务、保存点、未知提交、覆盖缺口、初始状态不一致、跨窗读源缺失、不同异常共存、分类环、预算恰好耗尽和缓存开关。篡改模型定义、来源、预算、谓词或证据必须被拒绝。新模型的反例缩减每次删除仍重新验证；`oneMinimal` 只在完成当前判定规则下全部剩余事务的单删检查后成立。

Windows 和独立 Linux PostgreSQL 18 CI 均运行真实数据库路径；缺少数据库或驱动时明确记为未执行。确定性场景保留每场景 20 轮；新增自由并发与故障场景另设运行记录，不拿前者充当后者。
