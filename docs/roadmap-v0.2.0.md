## 用户能够得到什么

工具逐步连接“真实采集 → 异常解释 → 反例缩减 → 证据重放 → 修复回归”。MoonBit 负责模型语义、来源校验、依赖分析、搜索、缩减和证据验证；可选适配器负责数据库连接与原始事实记录。

发布按能力分层说明：已有版本寄存器分析、明确配置的驱动采集、普通表特定路径、ORM 来源诊断、列表和关系事实分析可以分别交付。能诊断原始来源不表示已经证明任意 SQL 语义；支持一种数据模型，也不表示已经完成全部隔离模型分类。

## 采集与来源的共同约定

适配器记录原始 SQL、参数、实际交付结果、异常和事务事件，写入效果与读取观察分开。执行成功不等于结果已经读取完整；条件 UPDATE、UPSERT 和零行结果也不能自动当作 SELECT 读取。

初始化必须有清楚的一致快照与采集起点。每次写入使用独立版本身份，业务值相同仍可区分；身份、自增序号、线程返回时间和墙钟不自动构成提交顺序。业务行与来源元数据的关联须符合该入口的快照和 SQL 契约。

保存点回滚撤销写效果，保留此前已交付的读取；`RELEASE` 不表示事务提交。COMMIT 未确认继续保持未知，重连和重试使用新事务身份。日志损坏、丢失来源、外部写者范围不明或未支持操作进入覆盖报告；不从部分记录导出完整历史。

各入口声明自己的资源预算。有界持久化、窗口交接、来源闭包和安全清理按实际完成部分交付；正在使用的来源记录保持可追溯。稳定支持的日志格式和 v1/v2 重放规则保持兼容，新契约使用明确版本标识。

## 三种数据模型

| 模型 | 支持的事实 | 主要边界 |
| --- | --- | --- |
| 唯一版本寄存器 | 点读取、点写入、已声明版本顺序与事务状态 | 多写者顺序不由标识符生成顺序推断 |
| `append-list-v1` | 唯一元素身份的追加和完整有序列表读取，允许重复业务值 | 追加身份与业务值分开；不混入其他模型事务 |
| `relation-set-v1` | 有类型行的 insert/update/delete，完整点查、范围及字段等值/区间 AND 谓词事实 | 首版类型为 int64、布尔和明确比较规则的文本；NULL、任意函数、JOIN、聚合和子查询留待扩展 |

精确搜索容量与结构输入容量分别说明。当前有界寄存器搜索保留已验证的 12 个提交事务上限；列表和关系入口按各自声明的预算使用。搜索耗尽返回无法判定，完整搜索无解和预算中断是不同结果。大图入口不意味着精确枚举也达到相同容量。

关系查询的完整结果集合与多行写实际影响集合分开。PostgreSQL Read Committed 目标搜索、等待后重检等事实不足时保持覆盖缺口；`RETURNING` 集合不能作为已经完整读取谓词范围的证据。

各模型的具体输入、预算和可运行示例见 [v3 契约](v3-contract.md)、[列表模型](list-v3.md)及[关系模型](relation-v3.md)。

## 分类的增强方向

分类可以按已完成的类别分批交付，每个类别标明适用事实、模型定义及证据。以下仍是完整分类的目标，不是当前功能清单，也不是每版发布前必须全部完成的条件。

| 定义标识 | 计划反证规则 |
| --- | --- |
| `adya-pl-1-v1` | G0 写依赖环 |
| `adya-pl-2-v1` | G1a、G1b、G1c |
| `adya-pl-2.99-v1` | G1a、G1b、G1c、G2-item；G2-item 环至少包含一条项目反依赖，可同时含谓词反依赖 |
| `elle-generalized-si-v1` | 内部一致性违反、G1a、G1b、G1c、G-nonadjacent |
| `adya-pl-3-v1` | G1a、G1b、G1c、G2，包含项目和谓词反依赖 |
| `strict-pl-ss-v1` | G1a、G1b，以及加入已证明实时关系后的对应 G1c、G2 规则 |

G-nonadjacent 至少含一条反依赖，这些反依赖在环上两两不相邻，首尾也计相邻；G-single 是 G-nonadjacent 的特例。全局最短环与特定异常类别的证据分别处理。实时关系来自可比较的调用/完成事件或可核验因果关系；原始 Adya PL-SI 所需逻辑快照起点不由客户端 BEGIN 时间替代。参考：[Generalized SI](https://jepsen.io/consistency/models/snapshot-isolation)、[G-nonadjacent](https://jepsen.io/consistency/phenomena/g-nonadjacent)、[Adya 论文](https://publications.csail.mit.edu/lcs/pubs/pdf/MIT-LCS-TR-786.pdf)。

业务名称也逐步增加：只有操作模式与来源证据支持时，才标注丢失更新、写偏斜、不可重复读或幻读。报告解释某段历史和声明模型之间的关系，不认证数据库所有执行的隔离级别。

Elle 对照使用双方共同的原始事实，保留 unknown、超时、执行错误和差异。已冻结的 1,000 份寄存器与 1,000 份列表输入继续使用；完成一部分可以先公布该部分结果，尚未执行的记录保持可见。完整对照不再阻止无关的采集、模型或工具改进发布。

## 性能与发布

优化持续处理采集编码与额外写入、图索引与报告分配、搜索状态和缩减复验。目标仍包括图组提速与内存下降、困难搜索和大反例缩减、完整采集成本及逐级大图规模。历史数字和测量方法保留在 [执行安排](remaining-execution-plan.md)与[性能说明](performance.md)中，当前收益按对应实现和负载报告。

每版完成新增及受影响部分的正确性、兼容性和安装验证，提供变更说明和可运行示例；数据库功能有对应真实场景，性能结论有相同口径的样本。发布 GitHub 和 Mooncakes 后核对公开包并从新目录使用。较大的研究目标继续迭代，相关覆盖缺口和验证结果随支持矩阵说明。

发布说明保持简洁：功能、用法、兼容性、支持边界和必要验证摘要。完整算法、参考来源、许可证、测试与开发记录保留链接。v0.2.0 整理当时已发布的稳定能力；实际用户反馈、生产采用和赛事审核继续分别记录。
