# v0.3.6 candidate verification

The maintained integration runner executes the original 90 model SDK/CLI checks and 38 atomic-row SDK/CLI checks, plus the register/list and row examples. Both source and portable package consumers run those checks against their actual compiled core digest. Source consumers still build the complete core from source. Native/Wasm/JS core regressions retain the original typed cases; public interfaces do not merge old category or model namespaces.

The prior fixed Elle comparison is a separate experiment: 2,000 original register/list inputs, canonical `serializable` only. Its frozen implementation was `a967dc4` with core `ffdcce94…`. That run recorded 1,985 matches, zero differences, 12 unknowns and three non-comparable inputs. The original Elle JVM output was reused. This does not establish parity for fourteen models or relation histories.

[The previous technical reference](elle-fixed2000-previous-reference.json) records the original receipt and per-item digests without copying old runtimes or large output trees. The comparison must be rerun against the final merged candidate before claiming it for these new bytes. The original row interpreter corpus is a distinct test and is not added to the 2,000-case comparison count.

Final-candidate compilation, cross-target execution, independent review, fresh package installation and formal performance measurements have not been performed by this lightweight integration step. Existing formal preparation and earlier measurements remain tied to their original runtimes. Publication-order compatibility checks for v0.3.5 and v0.3.6 are added after the relevant versions are actually published; no unpublished candidate is labelled a public producer.
