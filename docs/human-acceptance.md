# 参赛者亲自验收清单

状态：**等待参赛者本人执行并记录**。自动测试、AI 操作和公开发布均不能代填这一项。

1. 从 GitHub Release 新下载 portable 包，核对 SHA-256，解压到新目录。
2. 查看 Node 版本并运行 `node dist/demo.mjs`；打开生成的中文报告。
3. 说明两事务写偏斜的两条依赖、为什么成环，以及删除任一事务后为什么不再保留相同异常。
4. 对缺失版本顺序案例说明 `consistent`、完整穷举 `violation`、预算耗尽 `inconclusive` 的区别；说明 `searched` 为什么不是数据库提交事实。
5. 运行公开 PostgreSQL 步骤，检查 20 个 RR 案例与 20 个 Serializable 回滚/重试对照，回放三个生成的 capsule。无数据库时记录未执行，并在提交前补做。
6. 解释 `oneMinimal` 的判定规则和适用预算，说明它不意味着全局最小。
7. 查看测试、失败性能记录、当前完整测量和边界；说明 AI 参与了什么，以及如何复核其结果。
8. 独立确认官方报名、入群、截止时间及提交材料；保存组织方回执。

请把本人执行日期、环境、下载版本/摘要、证据目录、上述问题的解释和待解决问题保存在自己的验收记录中。当前项目交付不包含人工签字，也未声明官方接受或获奖。
