# v0.5.0 完整模型调用性能

本页记录不可变索引复用和完整 SDK 调用的正式测量。三批测量的完整输出逐字节一致，四组控制负载均通过回退检查。关系模型组平均提速 1.081 倍，模型保持缩减组 1.044 倍；共同路径约 0.990 倍、组合推断约 1.004 倍。总体目标负载平均约 1.020 倍，峰值 RSS 基本持平；本轮未达到 1.3 倍提速和 20% 内存下降目标。旧实验不计作本轮收益。

## 实现范围

组合推断与基础模型分析原先分别建立原始来源和事务顺序索引。当前实现为一次组合调用建立一份不可变的 `ModelSourceV4`／`ModelOrdersV4`，供模块与基础模型读取。每个模块仍看到同一原始事实，无法通过修改调用者容器或前一模块的输出改变该索引。模块新增的约束只进入独立的扩展图，不进入原始程序的基础补全证书。

独立 `classify_models_v4` 仍自行核验输入。共享后嵌入的来源／顺序执行记录描述同一份原始核验工作；它们不是可累加的独立进程耗时。报告字段、来源引用、预算与逻辑计数保持原语义，不能通过减少检查次数、删边或省略证明来获得可比性。

关系模型先建立一份完整 scoped graph，再供各模型的投影读取。每项规则仍构造自己的投影、保持 WW／WR／RW 的项目与谓词范围，以及独立搜索预算和计数。完整来源、平行边和必要模型规则继续输出；不会用全局最短环替代类别检查，也不会把不同模型的必要义务混合成一个判断。

这些改动复用调用内部的不可变工作结果，不扩大数据模型、采集来源或精确搜索的支持范围。

## 推荐接口与兼容

| 工作流 | 推荐入口 | 验证策略 |
| --- | --- | --- |
| 既有寄存器／列表／原子行来源配置 | `classifyModelsV4` | 原始事实和独立模型选项 |
| 多模块推断与模型反证 | `classifyWithInferenceV4` | 调用者本地模块实现、顺序、参数、算法及预算 |
| 关系谓词逐模型分析 | `classifyRelationModelsV4` | 原始完整查询／写入、模型、逻辑客户端及实时策略 |
| 关系模型保持缩减 | `reduceRelationModelsV4` | 独立目标模型、来源闭包、候选及模型预算 |

模块完整标志不能授权模型相容。可靠反证不会被其他检查超时覆盖；新增约束尚无适用补全证明时保持 `unknown`。关系模型的十四个可选定义具有逐项检查入口，并不等于全历史可判定或与 Elle 的完整等价证明。原 v1–v4 入口和旧复现包继续遵循其既有算法、计数与预算规则。

来源、模型与缩减契约分别见[推断模块](inference-modules-v4.md)、[关系模型](relation-models-v4.md)和[模型保持缩减](relation-models-reduction-v4.md)。

## 分组基线

| 测量组 | 完整 SDK 调用 | 基线 |
| --- | --- | --- |
| 共同模型路径 | `classifyModelsV4` | 冻结 v0.4.2 运行时 |
| 可组合推断 | `classifyWithInferenceV4` | 冻结 v0.4.3 运行时 |
| 关系谓词模型 | `classifyRelationModelsV4` | 冻结 v0.4.5 运行时 |
| 可选缩减组 | `reduceRelationModelsV4` | 实际含同一接口与契约的独立冻结运行时 |

每组显式提供基线／候选 SDK 路径、源提交、用例及选项。对应公开包是否已经完成下载与安装核验，仍以该版本的交付收据为准；冻结的本地运行时不自动成为公开发布证据。新接口不会与旧版少检查或只输出摘要的接口计算提速。

共同路径覆盖寄存器、显式列表前缀和原子关系行，另保留类别环、受限预算与大量无关事务负载。关系组覆盖完整点查询、空结果谓词环、噪声及预算边界。图容量与精确枚举容量分开：大图可能完成图检查而不能执行完整补全，结果如实保留。

## 正式协议

使用维护中的 `scripts/model-performance-v050.mjs`。输入、选项和运行时先冻结，全部用例先比较完整输出字节；若判断、证据、计数或输出范围不同，该用例不能进入性能比较。复现包和产品版本元数据不计入本轮调用计时。

每用例、每实现运行 **5 次预热、30 次正式样本、3 批独立进程**。批次交替安排基线与候选顺序。测量完整 SDK 调用及完整 JSON 序列化，保留所有边、来源、证书和计数；不测只输出摘要的替代路径。

峰值内存由另一组独立新进程的 `process.resourceUsage().maxRSS` 记录，单位为 KiB，包含 SDK 导入、完整调用与完整输出序列化。另行记录新进程冷启动、导入时间、首次完整调用及输出字节数。冷启动表示新进程启动，不宣称清空操作系统磁盘缓存。

报告保留中位数、最近秩 P95、独立进程峰值 RSS、完整输出大小、每批原始样本及进程身份。目标负载用各用例比值的几何平均汇总；控制负载单列。控制组 P95 回退上限为 **10% 或 2 ms 中较大值**。分析提速目标为 1.3 倍、峰值 RSS 比目标为 0.8；缩减单列 1.25 倍提速目标。结果未达到时保留实际数值和失败记录，不改变测试预期或报告范围。

```powershell
node scripts/model-performance-v050.mjs --describe-cases
node scripts/model-performance-v050.mjs --config bench-config.json --output D:\ModelPerformance\new-run
```

配置需要显式声明 `exclusiveExecution: true`，并给每组提供目标负载与共同控制。正式执行前暂停本机编译、数据库测试、打包和其他测量。输出目录必须是新目录；记录输入、完整预检报告、运行时文件摘要、环境、脚本、原始样本及汇总清单。

`--smoke` 仅运行一批、一次预热和两份正式样本，用于检查工具流程。此模式始终标记 `formal: false`，不能用于本页性能成绩或发布收益。

## 正式结果

| 分组 | 目标负载数 | 中位耗时几何平均提速 | 峰值 RSS 比 | 控制组 |
| --- | ---: | ---: | ---: | --- |
| 共同模型路径 / v0.4.2 | 5 | 0.990× | 1.010 | 通过 |
| 可组合推断 / v0.4.3 | 5 | 1.004× | 1.001 | 通过 |
| 关系谓词模型 / v0.4.5 | 3 | 1.081× | 0.998 | 通过 |
| 模型保持缩减 / v0.4.5 | 2 | 1.044× | 1.001 | 通过 |

RSS 比小于 1 表示下降。共同路径约 1% 的耗时变化不作为收益；索引共享没有带来可证明的整体内存下降。全部 15 个目标负载合并的中位提速几何平均为 1.01965 倍、RSS 比为 1.00344。分析与缩减目标分别计算，不将合并值用于宣称任何一项达标。

每个负载和实现有 90 份正式计时样本；共 19 个负载、3,420 份样本，以及独立的新进程冷启动与峰值内存记录。完整报告大小从约几十 KiB 到 3.7 MB，序列化成本始终纳入比较。未用减少来源或改变计数换取收益。

完整中位数、P95、RSS、冷启动、输出大小、运行时逐文件摘要和环境见[测量收据](evidence/model-performance-v050.json)，380 份原始 worker 结果合并保存在[原始样本](evidence/model-performance-v050-samples.jsonl)。文件合并只减少存储条目，不改变样本内容；每条记录还绑定原始结果文件摘要。原完整证据目录的清单摘要也保留在收据中。

公开收据仅省略测量主机名称，原始记录保持不变。基线是给定源码和工具链编译的冻结本地运行时；公开下载的一致性按逐版发布收据单独记录，不能从本测量推定已经完成公开安装核验。
