# relation-set-v1 isolated core draft

This implements the frozen relation semantic contract on the original f33c8675 baseline, separate from all performance drafts. It has not changed the primary source, scripts or dist. It is an experimental semantic-facts model and does not turn arbitrary SQL, UPDATE RETURNING or partial cursor results into complete predicates.

Entry points: pub normalize_relation_capture_v3_json(text) -> String; package fn relation_v3_analysis(text, options_text) -> Json raise. The local SDK dispatch accepts normalizeCaptureV3 / analyzeV3 / verifyV3 / reduceV3 / makeCapsuleV3 / replayCapsuleV3 for relation-set-v1. The unrelated dislock SQL proof option is rejected. A real raw statement still creates a coverage gap. Input/report/replay versions for existing models are unchanged.

Types are complete signed int64 canonical decimal strings, JSON booleans and valid Unicode scalar text. Text comparisons decode supplementary scalars and compare code points without normalization; U+0000 and empty text keys are part of the model domain. Names follow the frozen ASCII syntax. Internal key indices use JSON array framing of relation, primary-key type and exact wire value, rather than ambiguous delimiter concatenation. Every producer version is globally unique.

The first phase validates structure, types and immutable original observations. Only a synthetic private metadata trace is passed to the existing register lifecycle normalizer for transaction/scopes/outcomes; no synthetic keys, operations, history or edges are exported. Public observations stay original. Effects include all actual row writes, including overwritten intermediates and tombstones, with the actual savepoint/rollback revocation event. finalWrites contains only the last unreverted write per structured relation/key, sorted by source sequence. Rollback preserves delivered reads. Releasing a scope does not commit it.

Unknown/future read or predecessor sources create permanent gaps, including in aborted transactions. Known wrong-key/relation/content, duplicate returned keys, nonmatching returned rows, tombstone, aborted and revoked sources produce descriptive findings only for committed journals. A later rollback does not invalidate a read or predecessor that was legal at its observation time. The analysis checks exact capacity and all gaps before exposing a source-proven violation. No G0/G1/G2/SI or SQL isolation label is inferred.

The exact interpreter searches only committed transaction permutations, executing every row query/write and scope action in each complete journal, including reads in later rolled-back scopes. State includes live versions and tombstones; each write checks existence and actual predecessor, and uses an inverse state trail for scope/candidate rollback. Queries scan live keys in canonical primary-key order, apply AND terms in original order with short circuiting, compare result size and then exact sorted key/version/full-row fields. No dependency graph algorithm or failed-state cache decides this model.

Budgets are search-only: each candidate attempt increments states, each semantic/scope action increments operationChecks; each predicate comparison, result-size comparison, and key/version/non-primary-field comparison increments once. The exact final allowed operation can complete a witness or exhaustion; needing another check returns inconclusive. Direct source proofs consume no search budget. Limits are 6 committed TX,128 raw relation ops for exact search,100000 states/1000000 checks; structural limits remain 8 relations,16 columns,512 TX,65536 events,10000 semantic ops,1024 distinct keys and100000 returned row references. Large/unknown coverage never becomes exhausted.
